# Product vision

**Create anything. Learn everything.**

Euler's Forge is one creative environment for people who make things in more than one medium.
Instead of five disconnected tools and a folder full of tutorials, it offers a single place where the
work and the explanation of the work live side by side.

## The problem

Creative software splits along two axes that both hurt:

1. **Discipline.** Design lives in one app, photo in another, motion in a third. A poster that needs
   a photo edit and an animated version means three files, three file formats and three mental
   models.
2. **Explanation.** Learning material is written for somebody else's version of the tool, in a
   browser tab, with no connection to the file in front of you.

The result is that beginners never start, and experienced people spend their time translating
between tools instead of making things.

## What the product is

- **One shell, many studios.** A project is created in a *studio* — Design, Photo, Video, Motion,
  Illustration, and eventually 3D — but the shell, project library, learning layer and asset
  catalogue are shared. Moving between disciplines does not mean learning a new application.
- **A visible core.** Documents, units, guides, metadata, history, export readiness and persistence
  behave the same way in every studio because they are one model, not six.
- **Learning where the work happens.** Lessons explain the tool you are looking at, in the same
  vocabulary the interface uses. A guided exercise ends by opening the real screen it describes.
- **Honest software.** Everything the interface shows is either working, or explicitly marked as
  planned with the reason. No pretend editors, no fake success, no decorative statistics.

## Who it is for

- **The curious beginner** needs one obvious starting point, a small vocabulary, and a first
  finished object within an hour. Home, the creation flow and the beginner lesson path exist for
  them.
- **The multi-disciplinary maker** needs canvas/unit/guide/metadata control, undo they can trust,
  exports in the right format, and fast movement between disciplines. The workspace inspector,
  history and export checklist exist for them.
- **The team later** will need shared projects, review states and asset governance. Those are
  roadmap items, deliberately absent rather than faked.

## What the product refuses to do

Recorded here because scope discipline is the hard part:

- No fake AI assistant, and no AI-generated content passed off as authored work.
- No fabricated analytics, vanity counters or “activity” charts.
- No marketplace economy or billing in the foundation phase; monetisation is a later, deliberate
  decision with its own record.
- No interface element that claims an editing operation that does not exist. If a control cannot
  work yet, it is disabled with the reason and the roadmap entry that changes it.
- No cloud requirement. Documents live in the browser, and the app says so on every surface that
  could imply otherwise.

## Phase 1 in product terms

This milestone proves the shell can carry specialists and teach at the same time:

- Home answers three questions: what can I make, how do I start as a beginner, where do I go for
  precise control.
- The creation flow produces a **real, validated document** that appears in the project library and
  opens in the workspace.
- The Design Studio workspace manages document setup end to end, with undo/redo and export
  readiness, and states plainly which editing tools it does not have yet (Phase 1 shipped no
  drawing or layer tools at all; Phase 2 added text and shape layers with select, move and resize).
- Studios, learning and assets are data-driven, so adding a discipline or a lesson is an edit to a
  registry rather than surgery on the application.
